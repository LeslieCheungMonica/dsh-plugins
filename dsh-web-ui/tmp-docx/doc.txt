4. 应用接入
4.1 新增应用
配置项说明：
应用名称：自定义（不可重复）
应用图标：自定义
应用编码：自定义（不可重复）
依赖应用：可选选择已接入应用作为依赖应用，共享依赖应用的组织及帐号信息
复用主帐号密码：复用授权主帐号密码(主帐号修改密码后也会同步修改绑定从帐号的密码)
登录帐号：
-主帐号，复用IAM主帐号登录应用系统（当接入应用的组织、帐号数据和IAM主账号一致时 选择次选项）
-从帐号，使用应用侧帐号登录应用系统（当接入应用有独立的组织、帐号数据时 选择此选项）
应用类别：
-BS应用，标识应用类型为BS架构，支持票据，标签，代填
-CS应用，标识应用为CS架构，仅支持代填
单点协议：当标识BS应用时，可选单点登录协议
-亚信票据，系亚信自研的单点登录协议，接入应用需要配合改造对接
-标签模式，通过识别登录窗口标签代填帐号，密码进行登录 ，仅支持登录帐号为从帐号
-表单模式，通过表单提交帐号，密码进行登录 ，仅支持登录帐号为从帐号
应用网关：
应用网关使用场景:使用票据/标签/表单模式进行单点登录;对应用访问进行加密，由http协议转为https协议;应用访问日志完整记录;应用页面增加安全水印;
登录工具：
支持当前浏览器（登录IAM时使用的浏览器）
支持本地工具（用户电脑上安装的工具）
支持远程工具（通过图形网关打开远程工具）
以上三中登录工具，除“当前浏览器”外，其余均需要在访问网关-运维网关-工具管理提前进行配置。
管理模式：
-托管，应用从帐号及密码通过通过在IAM进行管理，并将帐号信息同步至第三方应用系统
-自管，应用从帐号及密码可由用户在登录页录入或管理员从应用管理进行帐号管理，不与应用侧同步（自管应用场景常用于应用本身没有帐号体系，从而复用IAM的帐号作为自身帐号使用,单点也是使用IAM帐号进行登录）
匹配方式：
自动匹配 :手机号、邮箱 ，从帐号在反向同步过程或从帐号导入的过程中，根据选择项自动匹配符合的主帐号进行主从授权。
应用资源组：IAM测应用资源归属组
应用管理员：可编辑该应用的主账号
从帐号管理员：从帐号的中的管理员帐号（相当于第三方应用中的超级管理员）
是否涉敏：涉敏资源无法授权给非涉敏用户；
密码策略：应用下从帐号可使用的密码策略
应用同步方式：在应用列表点击“同步”按钮时，会使用以下方式全量拉取第三方应用的组织、从帐号数据。
-标准API：IAM调用第三方应用提供API（基于4A产品对外标准接口 4.1.4、4.1.12章节的报文结构）全量同步数据
-数据源：IAM通过数据源配置的sql，全量同步对应数据源中的全量数据。
应用推送：在IAM应用中对组织、从帐号进行的变更数据会推送给第三方应用系统，操作包括新增、修改、删除/批量新增、批量修改、批量删除 组织机构或从帐号。
-标准API ：第三方基于4A产品对外标准接口4.1章节定义的报文结构，提供的api接口地址
登出地址配置：
-标准API
-AIF集成（MQ）
应用侧组织跟节点：填写应用侧组织机构根节点id，多个以","逗号分隔
访问信息：
-亚信票据模式：访问信息配置应用侧单点登录地址即可
-标签模式：以demo应用为例
访问地址：应用的登录页面地址
用户名标识：应用登录页面用户名输入框的前端标识
密码标识：应用登录页面密码输入框的前端标识
登录标签标识：应用登录页面登录按钮的前端标识
是否要登录：标签模式代填完成帐号密码后是否要自动触发登录

demo资源登录页信息：

-表单模式：以demo应用为例
登录接口地址：应用侧登录信息表单的提交地址（非登陆页面地址）
表单登录代码：应用form表单登录前端代码

| HTML<form method="post"name="login"action="${url}">         <input id="username" name="username" type="text" value="${j_username}"/>         <input name="password" name="password" type="password" value="${j_password}"/>         <input name="Submit" type="submit" value="登录"/> </form> |

登录帐号元素：对应form表单中的用户名动态参数${j_username}
登录密码元素：对应form表单中的密码动态参数${j_password}

4.2 应用数据同步
为保证IAM组织、帐号 和 接入应用的数据的一致性，IAM提供正向（IAM应用数据推送至接入应用）、反向（第三方应用推送数据至IAM）的数据同步能力。
4.2.1 初始化同步
初始化同步指的是在IAM中新增应用后，在应用列表点击“同步”按钮时，根据应用配置中的应用同步方式项，全量拉取第三方应用的组织、从帐号数据。拉取方式可选两种：

标准API：IAM调用第三方应用提供API全量同步数据
在应用同步方式项中，选择“标准API”方式，并填写“应用组织采集服务地址”和“从帐号采集服务地址”（第三方应用基于4A产品对外标准接口 4.1.4、4.1.12章节的报文结构提供的API接口地址）

数据源：IAM通过数据源配置的sql，全量同步对应数据源中的全量数据。
当应用同步方式选择数据源同步时，需要点击应用数据右侧“...”按钮，点击'数据源配置'按钮进行数据源配置，如下图：

|  |  |

服务器连接：
数据源名称:自定义
业务类型:从帐号、组织机构  （完整的数据源方式同步，需要从帐号、组织机构两种配置都需要）
数据库类型：目前支持的数据库类型
链接地址：数据库链接的URL（例如：jdbc:postgresql://10.21.171.216:54321/postgres）
链接帐号：数据库登录帐号
链接密码：数据库登录密码
SQL语句：获取同步数据的sql查询语句
表名称：获取从帐号或组织机构对应的表明
是否选用分页查询：同步操作获取数据是否采用分页方式获取数据（默认分页）
分页记录数量：没穿分页查询数据条数（默认：100）
字段匹配规则：
服务器连接配置完成后，需要配置字段匹配规则，否则点击保存时会报错，切换到字段匹配规则tab页后，左侧显示IAM系统对应从账号/组织机构表的字段，右侧为数据源识别到的表字段，根据需要进行配置后即可保存。
4.2.2 正向同步（优先）
正向同步指的是在IAM应用管理中，对应用的组织机构、从帐号操作，会将数据同步至接入的应用，操作包括：新增、修改、删除/批量新增、批量修改、批量删除等。第三方应用提供接口，IAM为调用方。
应用配置中：
登录帐号选项：选择“从帐号”
应用类别： 选择“BS应用”
管理模式：选择“托管”
应用推送：开关打开，并配置组织机构新增地址、组织机构修改地址、组织机构删除地址、从帐号新增地址、从帐号修改地址、从帐号删除地址。以上地址为第三方应用基于4A产品对外标准接口4.1章节定义的报文结构，提供的api接口。（注意：当选择“单”时，会以4.1章节中单个同步接口报文结构同步，当选择“多”时，会以4.1章节中相关批量接口报文结构同步）

4.2.3 反向同步
反向同步指的是在第三方应用中，对应用的组织机构、从帐号操作，会将数据同步至IAM应用，操作包括：新增、修改、删除/批量新增、批量修改、批量删除等。IAM提供接口，调用方为第三方应用。
第三方应用可参考4A产品对外标准接口 4.2章节中 IAM提供的对外接口，进行调用。

7.1.1 接入流程

流程重要步骤说明：
应用前端再操作时，推荐使用统一拦截器，拦截全都操作请求，根据请求操作码，调用接金库接口进行是否金库触发判断；
调用金库/ais/configure/web/gold/trigger/app金库进行是否需要触发金库申请的判断，需要触发金库时再嵌入方式发开金库申请页面，接口参数参考4A产品对外标准接口 5.1应用资源操作类金库触发 ；
应用前端根据返回结果判断是否需要金库金库触发判断，当返回参数rsp=0时表示需要触发金库，此时再打金库申请界面
rep=0时，需要进一步进行金库申请审批操作，嵌入金库的金库页面地址后需要追加相应的参数，例如完整的路径为：http://ip:port/vault/v1/approve.html?operCode=qwe&mainLoginName=zhangss&subLoginName=admin&appCode=testApp&operContent=%E8%BF%99%E6%98%AF%E4%B8%80%E4%B8%AA%E9%87%91%E5%BA%93%E6%93%8D%E4%BD%9C&resKind=1&tenantId=1
参数说明：

| 参数 | 参数说明 | 备注 |
| operCode | 敏感操作编码 |  |
| mainLoginName | 登录资源主帐号登录名 | IAM侧登录帐号 |
| subLoginName | 登录资源从帐号登录名 | 资源侧登录帐号 |
| appCode | 资源编码 | 资源接入IAM约定的资源编码 |
| operContent | 敏感操作描述 | 避免乱码使用URLDecoder编码 |
| resKind | 资源类型 | 应用资源固定为‘1’ |
| tenantId | IAM侧租户ID |  |

审批结果会返回上层调用页面回调函数，审批结果格式：1(审批结果)#1234(流水号)#11234(token,可为空)，当审批结果为1时，表示审批通过，应用侧可以继续进行业务操作，其他审批结果编码参考接口文档；
当审批结果为1时，如果应用侧需要进一步确认审批结果是否正确，可以获取审批结果中的token参数，对审批结果进行二次验证；
审批结果二次验证接口为/gold/open/approval/check/token，根据二次验证接口返回结果判断是否继续进行操作，接口参数参考4A产品对外标准接口 5.8金库审批二次验证接口 ；

其中，时序图从第6步开始的第二个流程为可选流程，在应用前端接收到金库审批结果时，为防止金库绕行，可以通过第二个流程，即应用侧后端服务调用金库审批二次验证服务接口（/gold/open/approval/check/token）进行金库审批结果再验证。

金库服务开启token二次认证业务时，NACOS中需要增加以下配置：

| Properties#需要金库审批二次验证的应用的应用编码，多个应用编码以英文逗号（,）分隔，默认为空NEED_GOLDBANK_TOKEN_APPCODE= |

7.2 自定义金库审批页面接入
接入应用可以自定义审批页面，通过API接口的方式对接IAM金库。
流程图：

流程说明
用户进入应用资源进行敏感操作时，调用金库服务提供的应用操作类触发判断接口（/ais/configure/web/gold/trigger/app），判断是否触发金库审批，如果不需要触发金库，则业务继续；
判断金库触发判断接口返回的rsp和policyFlag字段，根据接口中的描述，判断金库审批是否在有效期或其他放行情况，如果是，则应用继续业务处理；
如果需要继续金库审批，查询金库申请原因列表（atom/amc/gold/reason/queryUserAvailable），此接口为选填，页面上支持下拉选择和手动输入两种方式，也可以不调用此接口，只支持一种手动输入方式；
应用侧根据判断接口返回的参数，弹出金库申请创建页面，输入金库申请信息，调用金库侧的金库申请接口（/gold/open/approval/apply），创建金库申请；
金库申请创建成功后，应用侧弹出金库认证页面，输入认证方式对应的审批信息，调用金库侧对应的认证接口；
金库认证成功后，会返回认证成功结果，应用侧业务继续；如果金库认证失败，则返回认证失败的结果，应用侧提示用户；
短信口令失效后，可重新调用短信口令重发接口(/gold/open/approval/smskey/resend)重新发送；
短信网关认证审批时，当应用侧则在金库申请创建成功后，自行轮询状态查询接口(/gold/open/approval/status/query)，查询审批结果。

现场审批为例，审批人输入密码后，调用接口/gold/open/approval/validate/acctpwd发起金库审批请求，接口参考4A产品对外标准接口 5.4 现场审批验证接口 ；
解析金库审批返回结果判断是否审批验证成功，接口参考4A产品对外标准接口 5.4 现场审批验证接口，当code=000000时表示审批成功，code!=000000时需要具体看msg返回信息；
金库验证成功后需要调用金库审批结果返回通知接口/gold/page/approval/goldbank-page/returnvalue验证金库审批最终结果，接口参考4A产品对外标准接口 5.13金库审批结果返回通知接口 ；
审批结果会返回上层调用页面回调函数，审批结果格式：1(审批结果)#1234(流水号)#11234(token),可为空)，当审批结果为1时，表示审批通过，应用侧可以继续进行业务操作，其他审批结果编码参考接口文档；
当审批结果为1且token不为空时，(为可选步骤)如果应用侧需要进一步确认审批结果是否正确，可以获取审批结果中的token参数，对审批结果进行二次验证，审批结果二次验证接口为/gold/open/approval/check/token，根据二次验证接口返回结果判断是否继续进行操作，接口参数参考4A产品对外标准接口 5.8金库审批二次验证接口 ；
金库审批二次验证接口返回审批结果，最终确定是否操作放行；
